# Velo — прототип голосового ввода

Запись через PipeWire, транскрибация через OpenRouter и вставка через виртуальную клавиатуру. Прототип для Niri/Linux без обработки текста. Аудио отправляется OpenRouter; временный WAV удаляется после обработки. Состояние и ошибки записываются в журнал в `XDG_RUNTIME_DIR/voice-dictation-UID/voice.log`, который доступен текущему пользователю. Успешный результат заменяет содержимое буфера обмена. Если фокус перешёл на другое окно, автоматическая вставка пропускается.

## Подготовка

Нужны Python 3 с `evdev`, доступ к `/dev/uinput`, Niri, `pw-record`, `wl-copy`, `notify-send` и `secret-tool`. Установи API-ключ в системное хранилище, вводя его только в терминале (не в чат):

```sh
secret-tool store --label='Voice Dictation OpenRouter' application voice-dictation service openrouter
```

Введи ключ в появившемся запросе. Требуется работающий Secret Service. Альтернатива для запуска из терминала — переменная `OPENROUTER_API_KEY`; не добавляй ключ в репозиторий или конфиг Niri.

## Проверка

```sh
python3 ~/Projects/voice-dictation/voice.py toggle
# произнеси фразу; затем снова:
python3 ~/Projects/voice-dictation/voice.py toggle
```

Дождись уведомления: текст вставится в исходное окно или останется в буфере, если окно изменилось. Журнал: `cat "$XDG_RUNTIME_DIR/voice-dictation-$(id -u)/voice.log"`. Запросы могут расходовать средства API. Модель по умолчанию — `openai/whisper-large-v3-turbo`; для запуска из терминала её можно заменить переменной `VOICE_MODEL`.

Для сочетания Niri привяжи команду `spawn "python3" "/абсолютный/путь/к/voice.py" "toggle";` внутри блока `binds`. На текущем компьютере назначено Super+Shift+Space. Приложение ещё не проверено на macOS; автоматическая вставка требует проверки в каждом приложении.

## Замеры задержки

Успешные запросы записывают длительность записи, ожидание API и время до команды вставки в `"$XDG_RUNTIME_DIR/voice-dictation-$(id -u)/timings.jsonl"`. Аудио и текст в этот файл не записываются. Время отсчитывается от получения сигнала процессом записи; в режиме удержания нужно также учитывать задержку 150 мс в `hold.py`. Команда вставки не подтверждает, что целевое приложение приняло текст.

Для сравнения моделей на одной записи запусти `python3 benchmark.py`. По умолчанию это 12 секунд аудио и шесть платных запросов. Аудио временно хранится в runtime-каталоге и удаляется по завершении; результаты, включая распознанный текст, сохраняются там же в `benchmark.json` с правами владельца. Следующий запуск перезапишет их.

Экспериментальная отправка фрагментов: `python3 chunked.py`, говорить, затем Ctrl+C. Аудио разделяется по коротким паузам после четырёх секунд, с ограничением семью секундами, и отправляется отдельными платными запросами во время записи с подсказкой русского языка. Результат показывается в терминале без автоматической вставки; границы фрагментов могут портить слова и пунктуацию. Время от остановки до текста сохраняется в `chunked-timings.jsonl`. Обычная диктовка не изменяется.

При запуске через `hold.py` фрагментный режим используется по умолчанию; результат вставляется только если фокус остался на исходном окне. Для прежнего режима установи `VELO_MODE=batch` в окружении пользовательского systemd-сервиса и перезапусти его. Короткие записи отправляются одним запросом. Фрагменты не перекрываются. Граница выбирается в тишине; при непрерывной речи на семи секундах остаётся принудительный разрез, поэтому ошибки на границе всё ещё возможны.

В режиме удержания транскрипция по умолчанию дополнительно отправляется в текстовую модель OpenRouter для лёгкой редактуры. Если запрос не удался, используется исходный текст. Чтобы отключить редактуру, установи `VELO_POLISH=0` в окружении пользовательского сервиса. Дополнительные запросы платные.

Редактура пока тестируется отдельно: `python3 polish.py --benchmark` сравнит исходную и отредактированную версию текста из последнего теста моделей. Для произвольного текста запусти `python3 polish.py`, введи текст и нажми Ctrl+D. Текст отправляется в OpenRouter отдельным платным запросом; в рабочую диктовку и буфер обмена редактура не вмешивается.

Стоимость новых успешных диктовок сохраняется локально без аудио и текста в `~/.local/state/velo/costs.jsonl`. Показать последнюю стоимость и среднее по полным записям: `python3 ~/Projects/voice-dictation/cost_stats.py`. Если API не вернул стоимость, запись помечается неполной; старые диктовки и отдельные неуспешные запросы в статистике могут отсутствовать.

## Восстановление диктовок

Стандартный режим удержания сохраняет аудио по мере записи и результаты фрагментов в `~/.local/state/velo/sessions/`. Эти файлы содержат личные данные; каталоги доступны только владельцу. Успешно собранный текст сохраняется до вставки, аудио после этого удаляется. Исходный и отредактированный тексты хранятся отдельно. Записи старше 24 часов удаляются при следующей диктовке или командой очистки; активные сессии пропускаются. Это не гарантированное удаление ровно через сутки, если Velo не запускается.

Из каталога проекта:

```sh
python3 recover.py list
python3 recover.py retry last
python3 recover.py copy last
python3 recover.py delete last
python3 recover.py cleanup
```

Вместо `last` можно указать идентификатор из списка. `retry` выполняет платные API-запросы только для недостающих фрагментов и при необходимости редактуры; текст копируется отдельной командой `copy`, без автоматической вставки. Если редактура снова не удалась, сохранённую исходную транскрипцию всё равно можно скопировать. Для отключения редактуры при восстановлении: `VELO_POLISH=0 python3 recover.py retry ID`.

Сетевые ошибки, HTTP 429 и 5xx повторяются до трёх раз с короткими паузами. Ошибки авторизации не повторяются. После сетевого тайм-аута сервер мог уже списать средства; такие расходы помечаются как неполные. Повторное восстановление обновляет стоимость той же сессии, а не создаёт новую диктовку в среднем.

При аварии процесса можно восстановить уже записанные в файл данные. При отключении питания последние несинхронизированные данные могут потеряться: принудительная синхронизация выполняется на границе фрагментов (не позднее семи секунд) и при остановке. Прежний режим `VELO_MODE=batch` пока не использует это восстановление.

Проверка с имитацией ошибок, без платных API-запросов: `python3 -m unittest -v test_recovery.py`.

## Панель состояния

Нативная панель GTK3 показывает запись, распознавание и редактуру. Нужны Python GObject и GTK3 (`python-gobject`, `gtk3` на Arch). Она появляется при диктовке; вручную открыть: `python3 status_ui.py`. Кнопки позволяют отменить текущую диктовку, скопировать последний сохранённый текст и скрыть панель. Отмена сохраняет сессию, запрещает вставку и отправку новых фрагментов после остановки; уже выполняющиеся запросы могут завершиться и тарифицироваться.

В Niri добавь правило для `app-id="^velo-status$"`: `open-floating true`, `open-focused false`. Это позволяет панели не забирать фокус у поля ввода. На текущем компьютере для открытия назначено Super+Alt+Space. Панель отслеживает стандартный фрагментный режим; прежний batch-режим пока не подключён.

Вид панели: тёмная капсула с анимацией состояния, кнопкой отмены и меню последнего текста. Полоски обозначают запись, а не измеренную громкость. После завершения диктовки панель скрывается через две секунды; вручную открытая панель остаётся видимой до следующей диктовки или команды скрытия.

Капсула не содержит текстовых статусов: ход работы обозначается анимацией, ошибки — цветом. Подсказки остаются при наведении и для средств доступности. Системные уведомления о диктовке отключены; сообщения сохраняются в журнале процесса.

На текущем компьютере капсула размещается у правого края по центру по вертикали через `default-floating-position x=16 y=0 relative-to="right"`. Непрозрачность 65%, при наведении — 95%.

## Разделение по паузам

Алгоритм `pause-v1` анализирует RMS аудио в окнах 20 мс. Пауза от 240 мс после четырёх секунд позволяет выбрать границу в середине тишины; максимальный фрагмент — семь секунд. Порог тишины — 30 единиц signed 16-bit PCM. Это простой детектор энергии, поэтому на шумном микрофоне он может не находить паузы; настройка требует проверки на реальной речи. Аудиосэмплы не выбрасываются и не дублируются. Последний фрагмент отправляется при отпускании клавиши.

Границы сохраняются до отправки в `boundaries.json` внутри сессии и используются при восстановлении. Старые сессии без этого файла восстанавливаются с прежними пятисекундными границами. В `chunked-timings.jsonl` добавлены `segmentation` и `chunk_seconds`, чтобы сравнивать размеры фрагментов и задержку. Ограничение семь секунд может увеличить ожидание последнего фрагмента — это нужно оценить на обычных диктовках.

Пустой ответ на тихий фрагмент (RMS каждого окна 20 мс ниже порога паузы) считается допустимым: он сохраняется вместе со стоимостью и не блокирует сборку текста. Пустой ответ на слышимое аудио остаётся ошибкой.

Если отдельный фрагмент с заметным звуком вернул пустой текст, Velo использует запасное распознавание всей записи целиком. Это добавляет платный запрос и задержку только при таком сбое. Учитывается стоимость как пустого ответа, так и повторной обработки. Если полная запись тоже не распозналась, аудио остаётся для восстановления.

## Резервный API-канал

При сетевой недоступности OpenRouter, HTTP 403/451, 408/429 или 5xx Velo может переключаться на `https://plusvibeapi.ru/v1`. Редактура и распознавание используют отдельный ключ:

```sh
secret-tool store --label='Velo PlusVibe' application voice-dictation service plusvibe
```

Переменная `PLUSVIBE_API_KEY` тоже поддерживается. `VELO_PROVIDER=auto` — выбор по доступности (по умолчанию), `openrouter` и `plusvibe` — принудительный выбор для тестов. Для окружения сервиса используй `systemctl --user edit velo-hold.service` и секцию `[Service]` с `Environment=VELO_PROVIDER=plusvibe`, затем daemon-reload и restart. API-ключи в конфиг сервиса не добавляй.

Модели резервного сервиса задаются через `VELO_PLUSVIBE_STT_MODEL` (по умолчанию `whisper-large-v3-turbo`) и `VELO_PLUSVIBE_EDITOR_MODEL` (`gemini-3.1-flash-lite`). После отказа OpenRouter последующие запросы две минуты используют PlusVibe, чтобы не повторять ожидание. Затем основной маршрут пробуется снова. Первый запрос при недоступности сети может занять до 15 секунд до перехода; после тайм-аута стоимость предыдущей попытки неизвестна.

Результаты сохраняют фактический сервис и модель. Стоимость PlusVibe.ru не считается долларами без подтверждённой валюты; статистика помечается неполной. Живая диктовка успешно прошла через PlusVibe: Whisper Turbo обработал оба аудиофрагмента, Gemini выполнил редактуру. В ранних диагностических запросах Whisper возвращал HTTP 502, поэтому временные ошибки сервиса всё ещё возможны. Состояние VPN при успешном тесте отдельно не подтверждалось. Документация: https://plusvibeapi.ru/docs/transcription.

## Нативный Rust-прототип

Начат поэтапный перенос: код и инструкция в [native/README.md](native/README.md). Это отдельный проверяемый вариант системной интеграции, а не полная замена Python. По умолчанию продолжает работать прежний сервис.

История нативных диктовок: `native/target/release/velo-native --history`. Окно позволяет посмотреть и скопировать сохранённый текст без микрофона и API-запросов. Для сессии с аудио без текста доступно платное повторное распознавание кнопкой «Распознать снова». Историю Python пока не показывает.
