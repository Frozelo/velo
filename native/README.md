# Velo Native — первый этап переноса на Rust

Изолированный прототип для CachyOS/Arch + Niri. Python-версия остаётся рабочей и запускается прежним сервисом. Rust-код не вызывает Python. Это ещё не замена всем её возможностям.

Сейчас реализованы:

- прямой захват PipeWire, mono S16LE, 16 кГц;
- удержание существующей клавиши F24 из keyd и остановка при отпускании;
- компактная капсула GTK4 с отменой;
- отправка записи целиком в OpenRouter с резервом PlusVibeAPI.ru;
- сохранение WAV при ошибке и результата перед вставкой;
- проверка фокуса Niri, буфер Wayland и виртуальная клавиатура для вставки;
- отдельное окно истории с просмотром, копированием и повторным распознаванием сохранённого аудио.

Пока не перенесены: разделение по паузам, редактура, восстановление фрагментов и настройки. История пока показывает только сессии Rust-версии. Ввод и вставка используют существующую интеграцию keyd/uinput; порталы и Layer Shell ещё предстоит проверить. Эта версия временно требует отдельного правила окна Niri.

## Сборка и проверки

Нужны Rust/Cargo, C toolchain, pkg-config, Clang/libclang, системные библиотеки GTK4 и PipeWire с заголовками. Во время первого запуска Cargo скачивает зависимости. Lockfile фиксирует их версии.

```sh
cargo build --release --manifest-path native/Cargo.toml
cargo test --manifest-path native/Cargo.toml
native/target/release/velo-native --doctor
native/target/release/velo-native --capture-test 2
native/target/release/velo-native --demo
```

`--capture-test` записывает 1–10 секунд, выводит длительность/уровень, затем удаляет данные из памяти; ничего не отправляет в API и не записывает на диск. `--demo` показывает анимацию без микрофона и сети. Для закрытия демо используй Ctrl+C в запускающем терминале.

## Живая диктовка

Не запускай два слушателя одной клавиши одновременно. Прототип проверяет активность Python-сервиса и отказывается запускаться вместе с ним.

```sh
systemctl --user stop velo-hold.service
native/target/release/velo-native --hold
# После теста: Ctrl+C, затем вернуть рабочую версию:
systemctl --user start velo-hold.service
```

Ключи читаются из тех же записей Secret Service, что у Python: `application=voice-dictation service=openrouter` и `service=plusvibe`. Поддерживаются `OPENROUTER_API_KEY`, `PLUSVIBE_API_KEY`, `VELO_PROVIDER`, `VOICE_MODEL`, `VELO_PLUSVIBE_STT_MODEL`. Не записывай ключи в репозиторий. `VELO_PROVIDER=plusvibe` принудительно использует резервный сервис. Запросы платные. В этой версии нет редактора текста.

Запись ограничена двумя минутами. Аудио накапливается в ограниченном буфере памяти и сохраняется при остановке, поэтому авария во время записи пока не восстанавливается. После остановки WAV хранится в `~/.local/state/velo-native/sessions/` (права 700/600); при успешном распознавании сохраняется `result.json`, WAV удаляется. При ошибке WAV остаётся. Автоочистки этих экспериментальных сессий пока нет. Отмена предотвращает вставку, но уже отправленный запрос может тарифицироваться.

Исходное содержимое буфера обмена заменяется. Если фокус окна изменился, автоматическая вставка пропускается. Смену поля внутри того же окна определить нельзя. Вставка в терминал не отправляет Enter.

## История диктовок

```sh
native/target/release/velo-native --history
# Только метаданные в терминале, без текста диктовок:
native/target/release/velo-native --history-list
```

Окно GTK4 показывает последние 100 нативных сессий: время записи, результат вставки, сервис, модель, длительность аудио и ожидания API. Выбери запись слева, чтобы прочитать текст и скопировать его кнопкой «Копировать текст». Копирование использует `wl-copy` и заменяет текущий буфер; автоматической вставки нет. Сообщение «Вставка запрошена» подтверждает только отправку клавиш целевому приложению.

История запускается отдельно от слушателя клавиши и может работать рядом с ним или с Python-сервисом. При открытии она не запускает микрофон, не читает API-ключи и не отправляет запросы. Второй запуск `--history` показывает уже открытое окно. Новые сессии появляются по кнопке обновления; в простое нет фонового опроса и анимации. Тексты загружаются только при выборе записи.

Читается `~/.local/state/velo-native/sessions/` либо `$XDG_STATE_HOME/velo-native/sessions/`. Старые сессии без отчёта тоже доступны. Повреждённый отчёт не скрывает остальные записи; если не читается сам текст, копирование отключается. Автоочистки и переноса истории Python пока нет.

### Повторное распознавание

Выбери сессию, у которой осталось аудио, но нет текста, и нажми «Распознать снова». Это платная отправка сохранённого WAV в тот же API с теми же настройками провайдера и резерва, что у нативной диктовки. Окно остаётся доступным: можно переключать записи, обновлять список и отменить обработку. Одновременно из окна запускается только одна задача. После завершения выбранная для просмотра запись сохраняется.

Восстановленный текст сохраняется атомарно в `result.json`, затем удаляется аудио. При ошибке или отмене без результата аудио остаётся. Буфер обмена и целевое приложение не меняются до нажатия «Копировать текст». Уже сохранённый результат используется без нового запроса; готовый или повреждённый `result.json` не перезаписывается. Общая блокировка сессии защищает от одновременного распознавания в истории и в новом нативном слушателе.

«Отменить» запрещает следующие запросы, но не обрывает немедленно уже отправленный блокирующий запрос. Если тот успел вернуть текст, Velo сохранит его. Закрытие окна тоже запрашивает отмену; процесс может некоторое время оставаться в фоне, чтобы дождаться текущего запроса и сохранить результат. Копирование и вставка при этом не выполняются.

Исходный `report.json` остаётся на месте. Последняя попытка описана в `recovery.json`, а каждый запуск — в отдельном `recovery-<ID>.json`: сервис, модель, длительность, диагностика API и признаки неизвестной стоимости. Журналы имеют права 600 и не содержат текста или ключей. До запроса сохраняется отметка `recovery_started`, чтобы при аварии было видно, что обработка могла начаться.

Дополнительный графический тест с имитацией API, без реальных запросов:

```sh
GSK_RENDERER=cairo cargo test --manifest-path native/Cargo.toml history::tests:: -- --ignored --test-threads=1
```

## Капсула в Niri

Для теста на текущем компьютере добавлено правило:

```kdl
window-rule {
    match app-id=r#"^org\.frozelo\.Velo\.Native$"#
    open-floating true
    open-focused false
    default-floating-position x=16 y=0 relative-to="right"
    focus-ring { off; }
    border { off; }
}
```

В живой сессии Niri подтверждены плавающее размещение и отсутствие смены фокуса. Саму вставку на живой диктовке ещё нужно проверить. Анимация обозначает состояние записи, а не измеренную громкость.

## Проверено на текущем компьютере

Прямой PipeWire-захват: за двухсекундный тест получено 1,98 с mono S16LE 16 кГц, без сохранения и отправки аудио. keyd и `/dev/uinput` доступны. GTK4-капсула отображается без смены фокуса.

На трёхсекундных замерах анимированной капсулы стандартный Vulkan-рендерер занял около 90 МиБ PSS, Cairo — около 31 МиБ PSS. CPU составил примерно 1% и 0,33% одного ядра соответственно. Это разовые замеры превью, не всего приложения во время диктовки. Поэтому Cairo выбран по умолчанию; другой рендерер можно явно задать через `GSK_RENDERER`. Итоговый расход при активной записи и запросах ещё предстоит измерить.

## Временный живой тест

```sh
bash native/test-live.sh start
bash native/test-live.sh status
bash native/test-live.sh stop
```

Скрипт временно останавливает Python-слушатель и запускает отдельный пользовательский systemd-сервис `velo-native-test`. По умолчанию используется PlusVibe, чтобы сначала проверить полную цепочку независимо от доступности OpenRouter. После остановки/ошибки или через 15 минут сервис возвращает Python, если он работал до теста. Для другого провайдера: `VELO_PROVIDER=auto bash native/test-live.sh start`.

Последовательность живой проверки: короткая фраза в Zen, фраза в Kitty (без Enter), отмена кнопкой во время записи, затем смена окна во время обработки. При смене окна должен обновиться только буфер, без автоматической вставки. Для отмены во время обработки нужен второй тест с более длинной записью. Запросы к реальным сервисам платные.

После записи в папке нативной сессии сохраняется `report.json` без текста и аудио: этап, результат, длительности и фактический сервис. `paste_requested` подтверждает отправку клавиш, а не получение текста приложением. `capture_end_to_result_seconds` считается от завершения захвата, а не от точного момента отпускания клавиши.

## Сетевые повторы и диагностика

На временные сетевые сбои, HTTP 408/429 и 5xx выполняется до трёх попыток с паузами 0,5 и 1 секунду, общий бюджет запросов — 60 секунд. Одна попытка ограничена 30 секундами, соединение — четырьмя. При доступном резервном ключе OpenRouter переключается на PlusVibe сразу, без повторов того же основного маршрута. Ошибки 400/401/402 не повторяются. Заголовок Retry-After с задержкой до 10 секунд учитывается; при большей задержке или формате HTTP-date автоматический повтор прекращается, чтобы не обращаться раньше разрешённого срока.

`report.json` хранит `api_attempts`: сервис, модель, номер, длительность, HTTP-код и тип ошибки (`timeout`, `connection`, `response_body`, `invalid_json`, `transport`, `http`). Ответы сервера и ключи в диагностику не включаются. Если ответ мог не дойти после обработки, попытка помечается `cost_unknown`: повторный запрос мог вызвать дополнительное списание.

Отмена проверяется перед попытками, во время паузы между ними и перед вставкой. Уже отправленный блокирующий HTTP-запрос не обрывается немедленно, но следующий после отмены не запускается. Аудио/полученный текст сохраняются по правилам прототипа.

Для вставки сохраняются `delivery_reason` и `delivery_checked_window_ids` — именно те проверки, по которым принято решение. Причины: `keys_sent`, `window_changed`, `target_window_unknown`, `current_window_unknown`, `cancelled`. Отдельный старый снимок `window_before_delivery_id` больше не используется.

## Предварительные релизы

Текущая версия — `v0.1.0-alpha.2`: добавлены история и повторное распознавание сохранённого аудио. Архив Linux x86_64 содержит бинарник и инструкцию запуска; SHA-256 опубликован отдельно. Это динамическая сборка на CachyOS/Arch, а не универсальный статический бинарник. На других дистрибутивах может потребоваться сборка из исходников.

Проверить версию: `velo-native --version`. В архиве `v0.1.0-alpha.1` окна истории ещё нет. Прототип пока не заменяет Python по настройкам, редактуре и восстановлению фрагментов.
